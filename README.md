# INEGO.dev

AI-инструменты для архитектурной визуализации поверх ComfyUI.

```
frontend/  React + Vite + TypeScript + Tailwind v4
backend/   FastAPI + PostgreSQL (авторизация, DeepSeek → промпт, клиент ComfyUI)
comfyui/   ComfyUI + FLUX.2 [klein] 4B / 9B в Docker (GPU)
```

## Docker (рекомендуется)

```bash
cp .env.example .env             # и впишите JWT_SECRET
docker compose up -d --build     # http://localhost:8080
docker compose logs -f           # логи
docker compose down              # остановить (данные БД сохраняются в volume pgdata)
```

- `frontend` — сборка Vite + nginx, отдаёт статику и проксирует `/api/*` в `backend`.
- `backend` — FastAPI. Наружу открыт только на `127.0.0.1:${BACKEND_PORT:-8010}` — для `npm run dev`.
- `db` — PostgreSQL 16, данные в volume `pgdata`. Таблицы создаются при старте бэкенда.
- `comfyui` — ComfyUI на GPU (нужен NVIDIA Container Toolkit / Docker Desktop с WSL2). При первом старте
  докачивает в volume `comfy_models` ~14 ГБ: `flux-2-klein-4b-fp8`, `qwen_3_4b`, `flux2-vae`, SegFormer, SAM 2.1, Depth Anything V2. UI — http://127.0.0.1:8188.
  FLUX.2 klein 9B (`flux-2-klein-9b-fp8` + `qwen_3_8b_fp8mixed`, ещё ~17 ГБ) скачивается, только если задан `HF_TOKEN`:
  репозиторий gated (FLUX Non-Commercial License) — сначала примите условия на странице модели на Hugging Face.
- Настройки — в `.env` в корне (см. `.env.example`).
- После изменения `VITE_USE_MOCK` нужна пересборка: `docker compose up -d --build frontend`.

## Авторизация

- `POST /api/auth/register` `{name, email, password}` · `POST /api/auth/login` `{email, password}` ·
  `POST /api/auth/logout` · `GET /api/auth/me`
- Пароли — Argon2. Сессия — JWT в httpOnly-cookie `inego_session` (SameSite=Lax, срок — `JWT_TTL_DAYS`).
- `/api/img2img` и `/api/inpaint` требуют входа.
- Без `JWT_SECRET` секрет генерируется при каждом старте — все сессии сбрасываются после перезапуска.
- За HTTPS включите `COOKIE_SECURE=true`.

## Frontend (локально)

```bash
docker compose up -d db backend  # бэкенд нужен для входа
cd frontend
npm install
npm run dev                      # http://localhost:5173
```

`/api/*` проксируется на `http://127.0.0.1:8010` (переопределяется переменной `API_PROXY`).
Генерация по умолчанию имитируется в браузере (`VITE_USE_MOCK=true`); вход и регистрация — всегда через бэкенд.

## Backend (локально, без Docker)

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
set DATABASE_URL=postgresql+asyncpg://inego:inego@localhost:5432/inego
```

Адрес ComfyUI задаётся через `COMFYUI_URL` (по умолчанию `http://127.0.0.1:8188`).

## Img2img экстерьера (FLUX.2 klein 4B / 9B)

Модель выбирается в запросе: поле `model` в `POST /api/img2img` — `klein-4b` (по умолчанию) или `klein-9b`.
Если веса выбранной модели ещё не скачаны в ComfyUI, бэкенд отвечает 503 с понятной ошибкой.

1. **DeepSeek** (`deepseek-flash`, vision) в два шага:
   - подробно разбирает референс (пресета или свой): время и погода, небо с hex-цветами, высота и сторона солнца,
     тени, лучи и дымка, трава и деревья (порода, сезон, цвета), состояние земли, искусственный свет, грейдинг
     в кельвинах и hex, «фотографичность». Разбор кэшируется по хешу картинки, встроенные референсы разбираются
     при старте бэкенда;
   - видит исходник и референс вместе и пишет описание под это здание: с какой стороны свет, какие фасады в тени,
     где на этой земле трава и деревья с референса.
   В промпт идут: замки камеры, геометрии и материалов + полный разбор референса + описание + блок фотореализма.
   Референс — эталон окружения: небо, свет, атмосфера, растительность и цвет переносятся, здание, его материалы
   и ракурс — строго с исходника; растительность не ставится перед зданием. Без `DEEPSEEK_API_KEY` — шаблонный промпт.
2. **ComfyUI**: исходник → `ReferenceLatent` (image 1) — модель редактирует его, а не рисует заново;
   референс (`backend/app/refs/exterior/*.jpg` или свой, ~1 Мп) → второй `ReferenceLatent` (image 2).
   Сэмплинг стартует с латента исходника; «Сила» 10–100% → denoise 0.9–1.0 (8 шагов, euler, cfg 1).
3. «Сохранить небо / фон / окружение» — сохраняется расклад зоны (где газон, дороги, деревья, соседние объёмы,
   облака), а сама зона перерисовывается фотореально в стилистике референса: зелёная плоскость становится газоном,
   условные деревья — настоящими, прозрачные объёмы — настоящими соседними зданиями. Полный рендер → нод
   `InegoKeepZones` размечает зоны ([comfyui/custom_nodes/inego_nodes](comfyui/custom_nodes/inego_nodes/__init__.py):
   небо — SegFormer, главное здание — SAM 2.1 по рамке от DeepSeek, деление фон/окружение — по классам и глубине
   Depth Anything V2, рябь масок убирается медианным фильтром) → `InegoZoneRestyle` ставит в зоны исходник в цвете
   рендера (стартовая склейка) → перерисовка только по маске зон (`ZONE_RESTYLE`, по умолчанию 0.875 = 7 шагов из 8,
   Differential Diffusion): image 1 — исходник (держит расклад), image 2 — референс, короткая отдельная команда
   «заглушки → настоящие объекты на тех же местах» + разбор референса. Здание вне маски не меняется.
   `ZONE_RESTYLE` меньше — ближе к исходнику (заглушки могут остаться), больше — фотореальнее, но расклад плывёт
   (на 1.0 пропадают облака и появляются лишние деревья). Фон — прочая застройка и всё позади здания,
   окружение — земля, озеленение, люди, машины перед ним.
4. Небо (экстерьер с референсом) — без масок и вклеек. DeepSeek в разборе указывает облачность (окты, процент,
   типы облаков) и рамку чистого неба на референсе. Без «Сохранить небо» вырезанное небо референса подаётся
   в основной проход третьей картинкой-образцом (image 3), облачность и её плотность заданы текстом (при чистом
   небе — «ни одного облака»). Цвет неба задаёт сама генерация. Подгонка цвета неба к референсу нодом
   `InegoSkyMatch` (по полосам от зенита к горизонту, маска — SegFormer) по умолчанию выключена — выходила криво;
   включается `SKY_MATCH` > 0 (сила, например 0.85).
5. Кадр ~1.5 Мп (`RENDER_MEGAPIXELS`) в пропорциях исходника; ответ — JPEG в точной пропорции исходника.

Свои референсы пресетов — заменить файлы в `backend/app/refs/exterior/` и описание `look` в `backend/app/presets.py`.

## Img2img на Qwen-Image-2.1 Turbo

`model=qwen-image-2.1` в `POST /api/img2img` — та же логика нейрорендера, что на FLUX (камера, геометрия и материалы
с исходника; небо, свет, атмосфера, растительность и грейдинг — с референса; галочки «Сохранить небо / фон /
окружение»), собранная под родной пайплайн 2.1 ([backend/app/comfy.py](backend/app/comfy.py) `build_qwen21_workflow`):

- картинки — входы `TextEncodeQwenImage21`: `<image1>` — исходник (холст), `<image2>` — референс (~0.5 Мп); энкодер
  Qwen3-VL читает их и вставляет латентами в последовательность (вместо `ReferenceLatent`). Образца неба (image 3) нет:
  каждая картинка удлиняет последовательность, и на 16 ГБ ComfyUI падал по CUDA OOM (процесс перезапускался —
  «Генерация не удалась»);
- запрос — по правилам официального переписчика 2.1: начинается с действия, у каждой картинки названа роль, картинки
  только тегами `<imageN>`, один абзац; смена «медиума» (3D-рендер → фото) — явная цель правки, иначе 2.1 сохраняет
  медиум входа. Объекты сцены (улицы, машины, люди, соседние здания, деревья) перечислены как остающиеся; стиль
  референса — текстом (разбор DeepSeek): по картинке 2.1 переносит его слабее. Без DeepSeek (шаблон) 2.1 почти
  копирует черновик, поэтому описание при сбое запрашивается повторно;
- кадр ~1.5 Мп (`QWEN21_RENDER_MEGAPIXELS`), стороны кратны 32; 8 шагов Turbo, cfg 1;
- «Сила» не применяется (в UI ползунок неактивен): у Turbo нет шкалы по стартовому шуму — на одной картинке σ 0.978
  дал копию черновика, 0.979–0.980 и 0.984–1.0 — полное фото, 0.981 — полупереход с призрачными заглушками;
- старт — с чистого шума (пустой латент энкодера в размере `<image1>`). Со старта от латента исходника (σ ≤ 0.98) 2.1
  на грубом CG-рендере почти копирует вход — меняется только цвет; σ 0.99–0.995 не помогает. Зато с чистого шума
  2.1 слегка перекадрирует сцену (здание смещается на 2–5% кадра) — это снимает нод `InegoAlign`
  ([comfyui/custom_nodes/inego_nodes](comfyui/custom_nodes/inego_nodes/__init__.py)): масштаб (±8%, грубо и точно)
  и сдвиг (пик взаимной корреляции карт контуров) до исходника, открывшийся край — несдвинутым результатом;
- VAE 2.1 декодирует RGBA — альфа отрезается (`SplitImageWithAlpha`) перед нодами совмещения и зон;
- «Сохранить зоны» — после совмещения те же `InegoKeepZones` / `InegoZoneRestyle`, перерисовка по маске — Differential
  Diffusion поверх `QwenImage21Cache`, `QWEN21_ZONE_STEPS` (6) шагов из 8. В команду зон для 2.1 не идёт перечень
  растений референса — его 2.1 читала как «добавить саженцы и кусты».

Время на RTX 5080 16 ГБ: ~55 с, с сохранением зон ~2 мин. Лучше всего переносятся пресеты с выраженным светом
(«Золотой час», «Естественный»); на «Дне» (солнце за камерой) свет выходит плоским. **Лицензия Qwen Research — только
некоммерческое использование.**

## Модели Inpainting: FLUX.2 klein, Qwen-Image-Edit-2511, Qwen-Image-2.1 Turbo

Выбор в шапке (поле `model` в `/api/inpaint`); Qwen-Image-Edit-2511 — только Inpainting (в Img to Img рендер на klein 9B), Qwen-Image-2.1 — и в Img to Img.
При переключении между семействами бэкенд выгружает прежние веса (`POST /free`) — вместе они не помещаются.
ComfyUI запускается с `--reserve-vram 2` (`COMFYUI_ARGS`): на 16 ГБ без резерва 2.1 падает с OOM на второй правке.
Если ComfyUI всё же отвечает «out of memory», бэкенд освобождает память (`POST /free`) и один раз повторяет задачу.

- `qwen-edit-2511` — GGUF Q4_K_M + Lightning LoRA (4 шага), плагин ComfyUI-GGUF. Родной способ модели: `Picture 1` —
  кроп, `Picture 2` — тот же кроп с тонким красным контуром области правки (отдельную ч/б маску 2511 не учили
  понимать, пометки — понимает). Латент кропа без заморозки по маске: модель перерисовывает кадр целиком по инструкции,
  вклейка берёт только область правки; протёкший контур убирает зачистка.
- `qwen-image-2.1` — **Qwen Research License: только некоммерческое использование** (для продукта нужна коммерческая
  лицензия Alibaba). int8 Turbo (8 шагов по фиксированному расписанию), **родной способ локальной правки** (блог Qwen):
  `<image1>` — кроп, `<image2>` — отдельная ч/б маска (белое — где править: выделение + рамка объекта в натуральную
  величину при добавлении, выделение с тенью при удалении). Латент не замораживается — модель перерисовывает кроп
  целиком и сама сохраняет остальное; вклейка по-прежнему берёт только область правки. Запрос — с действия, остальное
  одной фразой («Everything outside the marked region stays…»), картинки — тегами `<image1>`, `<image2>`.
  Красная подсказка не используется. Второй прогон — частичный шум от латента самого кропа (VAE 2.1).
  Кроп для 2.1 — ~2 Мп (`QWEN21_MEGAPIXELS`): на ~1 Мп объект на большом рендере (4K) рисовался вдвое мельче итогового
  и выходил «пластиковым». В запросе при добавлении: внутри отмеченной области земля, газон, плитка и стены остаются как
  были — иначе модель перерисовывала всю рамку (газон превращался в плитку).
  Запрос пишет DeepSeek в роли официального переписчика Qwen: системный промпт `prompt_rewrite/prompts/
  system_prompt_edit.txt` из QwenLM/Qwen-Image-2.1 (лежит в `backend/app/prompts/qwen21_edit_rewrite.txt`), картинки
  `<image1>` (кроп) и `<image2>` (маска), запрос пользователя как есть; в 2.1 уходит его `rewritten_prompt`. Свой
  переписчик Qwen3.5 не ставится. Без DeepSeek — шаблон.

Файлы моделей докачивает `comfyui/entrypoint.sh` (`QWEN_EDIT`, `QWEN21` — `false`, чтобы не качать).

## Фотореализм в промптах

Все промпты для моделей картинок заканчиваются блоком «реального фото» (`PHOTOREAL` для Img to Img, `REALISM_EDIT` и
`REALISM_REMOVE` для Inpainting в `backend/app/prompting.py`). По гайдам BFL (FLUX.2) и Qwen-Image: описывать как
фотограф — камера, объектив, свет, фактура и мелкие несовершенства (износ, неровность, поры кожи, асимметрия, зерно
сенсора); для правок — «та же камера, тот же кадр». Без «8k / masterpiece / ultra-detailed / flawless / render» — они
тянут в CGI — и без отрицаний: FLUX не поддерживает негативные промпты, а отрицание фокусирует модель на запрещённом
(при cfg 1 негативный промпт к тому же не используется). Промпты для DeepSeek (текстовой модели) отрицания содержат.

## DeepSeek: Flash / Pro

Переключатель в шапке сайта (общий для Img to Img и Inpainting, запоминается в браузере) выбирает модель DeepSeek
для разбора сцены, оценки размера и места объекта и инструкций: поле `llm` в `POST /api/img2img` и `/api/inpaint`
(`deepseek-flash` | `deepseek-v4-pro`, список — `DEEPSEEK_MODELS`, `GET /api/llm-models`). Кэши разборов и инструкций
раздельные по модели. Модель генерации (FLUX.2 klein 4B / 9B) от этого не меняется.

## Inpainting: удаление и правка (FLUX.2 klein 4B / 9B)

`POST /api/inpaint` — `image`, `mask` (PNG, белое — область), `mode` (`remove` | `edit`), `prompt`, `model` (`klein-4b` | `klein-9b`), `seed`.
`prompt` — необязательное уточнение, что именно удалить в выделении («люди», «машина»): удаляется только это,
остальное внутри выделения остаётся. Пусто — удаляется всё выделенное.
Ответ — JPEG в полном разрешении исходника, сид в `X-Seed`. Код — [backend/app/inpaint.py](backend/app/inpaint.py).

1. Маска расширяется (~4% размера объекта) и протягивается вниз на 8% его высоты — под контактную тень у ног и колёс.
2. Кроп с контекстом (маска + её размер с каждой стороны, не меньше 512 px) приводится к ~1 Мп (`INPAINT_MEGAPIXELS`):
   мелкий объект на большом кадре получает полное разрешение модели.
3. DeepSeek видит кроп с подсвеченной областью и называет, что удалить и что должно быть на его месте
   (продолжение окружающих поверхностей); заметную тень за обводкой добавляет к маске. Без ключа — общая формулировка.
4. ComfyUI: кроп — `ReferenceLatent` (image 1), инструкция «Remove … In its place show …», шум только под маской
   (`SetLatentNoiseMask`, 8 шагов, Differential Diffusion по мягкому краю).
5. Результат вклеивается в исходник по растушёванной маске — остальной кадр не меняется.

**Добавить / изменить** (`mode=edit`, `prompt` обязателен — «деревянная скамейка», «серый Porsche 911»).
Тип правки задаёт первое слово запроса: «добавь / поставь / посади / размести / нарисуй / установи» — новый объект;
«измени / замени / поменяй / перекрась / сделай» — меняется выделенное, и DeepSeek выбирает: «изменить» (материал,
цвет, порода — место, размер и форма прежние, запас 3%, рамка не строится) или «заменить» (другой объект: человек →
собака — старое исчезает с тенью, новое встаёт на то же место в своём размере, как при добавлении). Без слова тип
решает DeepSeek. Окно правки показывает, как понят запрос, подсказки начинаются
со слова-команды.

При добавлении выделение задаёт место, а не размер:
1. DeepSeek видит весь кадр с отмеченной областью и крупный план. По соседним объектам (двери, этажи, люди, машины,
   плитка, бордюр) и линиям перспективы он оценивает натуральный размер объекта и даёт его рамку; меряет свет, тени,
   баланс белого, дымку, глубину резкости и зерно кадра; отмечает, добавляется объект или меняется существующий.
2. Рамка ставится низом на нижний край выделения (точку касания земли): маска размером с собаку → Porsche в натуральную
   величину. Положение рамки от DeepSeek не используется — на вертикальных кадрах он промахивается.
3. Генерация по выделению + рамке + запасу 8% (`EDIT_ROOM`) и дополнительно вверх на четверть высоты рамки
   (`EDIT_HEADROOM`): головы, кроны и верхушки фонарей выходят выше оценки DeepSeek, иначе их срезает край генерации.
   При добавлении и замене красной разметки на подсказке нет: модель её копировала — кольцо по обводке, красную
   металлическую дугу по контуру рамки, красные пятна и дорожки на земле от заливки. Место задаёт область генерации
   (рамка в натуральную величину + запас), размер — текст инструкции. Разметка (image 2 — кроп с полупрозрачной
   заливкой выделения) остаётся только для «изменить», где она показывает, что именно меняется.
4. Вклейка: целиком — только выделение пользователя; из рамки и запаса — то, что модель заметно изменила
   (`CHANGE_THRESHOLD`) и что связано с выделением, без дыр. Часть объекта за рамкой не обрезается, а соседи, которых
   задела приблизительная рамка (собака рядом с новой машиной), остаются пикселями исходника. Клочки изменений
   сливаются «мостиками» (`CHANGE_BRIDGE`) — ажурная крона берёзы не теряется; объект, который модель поставила
   чуть в стороне от маленького выделения, засчитывается, если начинается в якорной зоне (`ANCHOR_REACH`).
4а. Вклейка при «добавить / заменить» — только сам объект и его тень: нод ComfyUI `InegoObjectMask` берёт изменения рядом
   с выделением, их рамку и центр выделения отдаёт SAM 2.1 и получает точный силуэт объекта; тень — связанные с объектом
   пиксели ниже его середины, ставшие темнее, — накладывается только затемнением: отношение сглаженных яркостей
   (без текстуры генерации) с весом по области тени, размытой на ~4% размера объекта, — без видимого края (бинарная
   маска с резким краем давала пятно на плитке). Свою тень не дорисовываем — только та, что нарисовала модель.
   Тень ищется только у земли (ниже ног), без тонкой полосы вдоль контура и нитевидных обрывков (иначе — тёмная
   обводка вокруг кроссовок); край объекта берётся с чуть сжатой маски. SAM — в два прохода: рамка по изменениям
   растягивается на перерисованный моделью фон (стенд за спиной), поэтому второй проход идёт с рамкой по основному
   силуэту (тонкие отростки срезаны, низ — как был, стопы и колёса не подрезаются). Тонкие края у ног, которые SAM
   не взял, добираются по изменениям.
4б. План и рамка на канвасе: при «добавить / заменить» фронт сначала вызывает `POST /api/inpaint/plan` (тот же разбор
   DeepSeek, кэшируется) и показывает рамку объекта — её можно двигать и растягивать, низ рамки — где объект касается
   земли. Поправленная рамка уходит в `/api/inpaint` полем `box` («x1,y1,x2,y2» в долях кадра). Рамка заменяет
   выделение, а не склеивается с ним в полосу (две слипшиеся машины): выделение остаётся только внутри рамки, а если
   рамку отодвинули — им становится нижняя треть рамки.
5. Зачистка протёкшей разметки (красное, которого в исходнике не было): тонированный исходник — цвет ровно смесь
   исходника с цветом разметки (`MARK_COLOR`), а окна, швы, травинки на месте; и тонкие линии насыщенного чисто-красного,
   не прилегающие к красному пятну. Красные объекты (купол, футболка) — новая структура и пятно, не трогаются; кожа и
   терракота оранжевее. Если в запросе есть красный цвет, зачистка выключается.
6. Снятие вуали (добавить / заменить): где модель залила фон за объектом белёсой дымкой — тот же фон, светлее и
   бледнее, структура совпадает с исходником (`VEIL_*`), — возвращаются исходные пиксели.
7. Второй прогон (добавить / заменить) — как в фотошопе: объект с полем 15% (`REFINE_PAD`) вырезается из результата,
   растягивается до ~1 Мп и перерисовывается по своей маске на 5 шагах из 8 (`REFINE_STEPS`; на 6 уже меняется цвет
   одежды) с явным списком дефектов, потом уменьшается и вклеивается. Лечит то, что в объекте есть: размытое лицо и
   руки, полупрозрачные части, смазанные шлейфы. Недостающую часть (голову) не дорисует — образец для модели это
   результат первого прогона, и она его воспроизводит. Выигрыш в детализации заметнее на больших исходниках.
